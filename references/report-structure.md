# 实验报告结构规范

按实验类型挑骨架，再把 `content.json` 的 `sections` 填满。默认六章，学校有模板时以模板章节为准，只保留模板要求的部分。

## 一、通用骨架（六章）

| 章节 | 写什么 | 篇幅 | 必备内容 |
| --- | --- | --- | --- |
| 一、实验目的 | 做完这个实验"能做什么"，3~4 条 | 80~150 字 | 动词开头：能设计、能实现、能分析 |
| 二、实验环境 | 真实软硬件版本，表格呈现 | 表格 1 张 | 操作系统 / 语言版本 / 数据库 / 工具 / 依赖 |
| 三、实验内容与原理 | 题目要求 + 关键原理 + 设计方案 | 400~800 字 | 至少 1 张设计图（E-R / 架构 / 流程） |
| 四、实验步骤 | 按"做了什么"分步，配关键代码 | 600~1200 字 | 3~6 段无注释代码 + 步骤说明 |
| 五、实验结果 | 运行截图 + 数据表 + 与预期的对照 | 300~600 字 | 3~6 张真实截图 + 1 张结果表 |
| 六、实验总结 | 只讲 2~3 个具体问题 | 200~450 字 | 第一人称、口语、有未解决的问题 |

正文总量（不含代码）控制在 2500~4000 字。低于 2000 字显得敷衍，超过 5000 字老师不会细看。

## 二、实验目的怎么写

不要抄课程大纲的"掌握 XX 技术"。改写成可验收的能力：

- 差：掌握数据库的设计方法。
- 好：能根据选课场景画出 E-R 图，并把 m:n 联系拆成独立的关系表。
- 差：熟悉 Java 面向对象编程。
- 好：能用继承和接口把三种图形的面积计算统一到一个方法里。

## 三、实验环境怎么写

必须与真实机器一致。用 `check_env.py --md-out env_table.md` 生成表格，不要凭印象写版本号。

表格三列：项目 / 版本或配置 / 说明。行数 4~7 行即可，别把 `pip list` 全贴上去。

若替换了技术栈（例如课程要求 MySQL，实际用 SQLite），在该节末尾加一句：

> 本机未安装 MySQL 服务，实验使用 SQLite 3.43 完成，SQL 语法除少量方言差异外与课程要求一致，建表与查询语句未做实质改动。

## 四、实验内容与原理怎么写

三段式：

1. **任务拆解**：把题目要求翻译成 2~4 个要解决的问题。
2. **原理**：只写这次真正用到的机制（例如"复合主键保证选课记录唯一"），不要抄教材。
3. **方案**：给出设计图，再说明为什么这样设计。有取舍的地方点一句，例如"没有用触发器统计人数，因为数据量小，查询时聚合更直观"。

配图规则：本节通常 1~2 张（E-R 图、架构图、流程图），不要超过 2 张。

## 五、实验步骤怎么写

按"能复现"的标准写，每步包含：做什么 → 关键代码 → 结果如何。

- 步骤标题用 `（1）创建数据库与数据表` 这种形式。
- 代码只贴关键片段，单段 15~60 行；超过 60 行就拆成两段，中间用文字过渡。
- 完整代码放附录或工程目录，报告里不贴全量。
- 每段代码前一句说明它在做什么，后一句说明这段验证了什么。

## 六、实验结果怎么写

结果不是"截图打包"，而是"证据 + 解读"：

- 图前一句话说明这次运行的条件（输入了什么、连的哪个库）。
- 图后一句话说明从图上能看出什么（"返回 4 行，数据结构平均分最高"）。
- 关键数据用三线表再汇总一次，方便老师核对。
- 有异常结果也要写：超时、报错、结果与预期不符，说明原因和后续处理。

## 七、实验总结怎么写

见 `writing-style.md`。核心：**只讲部分内容**，不要面面俱到，不要写成知识点总结。

## 八、四类实验的差异化要求

### A 编程语言 / 算法类（C、Java、Python、数据结构）

- 必须有：完整可运行代码（无注释）、至少 3 组测试输入输出、复杂度或边界分析。
- 推荐章节变体：实验目的 / 实验环境 / 算法思路 / 程序实现 / 运行结果 / 总结。
- 图表：流程图 1 张 + 运行结果截图 3 张以上（正常、边界、异常）。
- 结果表：输入 → 期望输出 → 实际输出 → 是否通过。

### B 软件开发 / 企业级应用类（Web、Spring Boot、SSM、Vue、小程序）

- 必须有：系统架构图、模块划分、关键接口说明、页面运行截图、启动日志。
- 推荐章节变体：需求分析 / 系统设计 / 数据库设计 / 关键实现 / 运行效果 / 总结。
- 图表：架构图 1 张 + 数据表结构 1 张 + 页面截图 3~5 张。
- 截图前必须真实启动服务，截图中要能看到真实数据（不是 Lorem ipsum）。
- 接口用三线表列出：方法 / 路径 / 入参 / 返回 / 说明。

### C 数据库设计与开发类（建库建表、SQL、触发器、存储过程、范式）

- 必须有：E-R 图、关系模式（下划线标主键）、建表 SQL、数据量说明、查询结果。
- 推荐章节变体：实验目的 / 实验环境 / 需求与 E-R 设计 / 逻辑结构设计 / 数据操作与查询 / 结果与分析 / 总结。
- 图表：E-R 图 1 张（`er` 类型）+ 表结构截图 + 查询结果截图 + 可选执行计划截图。
- 建表语句集中在一段代码里，约束（主键、外键、CHECK）必须体现。
- 查询要覆盖：单表条件、多表连接、分组统计、排序，各配一次真实结果。

### D 软件工程 / 计算机理论类（需求、UML、测试、OS、网络）

- 必须有：模型图（用例图/类图/时序图）、测试用例表、测试记录。
- 图表：类图或架构图 1~2 张 + 测试结果表。
- 测试用例表五列：编号 / 输入 / 预期 / 实际 / 结论。
- 操作系统、网络类实验以命令输出截图为主（`ps`、`top`、`ping`、`tracert`），命令要能看出参数。

## 九、实验要求 → 章节对应

课程要求里常见的表述，落到哪一章：

| 要求原文 | 落到 |
| --- | --- |
| 分析……需求 / 画出 E-R 图 | 三、实验内容与原理 |
| 编写程序实现…… | 四、实验步骤（代码） |
| 给出测试数据与运行结果 | 五、实验结果 |
| 分析时间/空间复杂度 | 五、实验结果（表）或总结 |
| 说明遇到的困难与解决办法 | 六、实验总结 |
| 提交源程序 | 附录或工程目录，正文只贴关键段 |

## 十、字数与图表配比参考

| 项目 | 建议量 |
| --- | --- |
| 图片 | 3~6 张（含 1~2 张设计图） |
| 表格 | 2~4 张（环境、结果、测试用例） |
| 代码 | 3~6 段，总行数 ≤ 200 行 |
| 每张图的说明文字 | 1~2 句，不要写成小作文 |
